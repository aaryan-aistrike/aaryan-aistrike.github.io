## Who they are

UTA0576 is a threat actor tracked by Volexity, first observed exploiting a previously unknown authentication-bypass-to-root exploit chain against Ivanti Connect Secure VPN appliances beginning around 2026-10-03 (with some honeypot telemetry suggesting activity as early as 2026-10-01). Volexity disclosed the activity on 2026-10-13 after finding it on a single customer's fully patched appliance. Unlike most Ivanti Connect Secure intrusion sets publicly tracked to date, which tend to be nation-state espionage operations, Volexity assesses with low confidence that UTA0576 is financially/criminally motivated rather than state-sponsored.

## Behavioral pattern

- **Three-stage chain to unauthenticated root.** The group chained an authentication-bypass flaw, a race-condition file-upload RCE, and a separate, still-unpatched privilege-escalation zero-day to go from zero access to root-level code execution on the appliance with no valid credentials at any point.
- **Header-spoofing auth bypass.** The entry point (tracked as **CVE-2026-104935**, CVSS 8.6) abuses the public `welcome.cgi` login endpoint: the appliance decides whether authentication is required based on the requested URL, but then routes the actual request to whatever script is named in an attacker-controlled `X-DSCGI-PATH` header - letting the request reach protected, authenticated-only code paths without ever authenticating.
- **Race-condition upload RCE.** The appliance's upload handler briefly writes an uploaded file to disk before validating and deleting it. UTA0576 won that race by firing parallel requests - one to upload a malicious Perl payload, a second (also via the `X-DSCGI-PATH` header trick) to invoke it - executing the payload in the narrow window before cleanup.
- **Unpatched root escalation.** To go from the web application's service-level access to full root, the actor chained a separate zero-day in the privileged `dsinvoked` service and its DSCache configuration store. As of disclosure, Ivanti had patched the auth-bypass/RCE step but the privilege-escalation flaw remained unfixed, with a patch still in development.
- **No backdoor, no persistent C2.** The actor passed commands and retrieved results entirely through the HTTPS exploit-chain requests themselves rather than dropping a web shell or backdoor - leaving a minimal persistent footprint on the appliance.
- **In-memory evasion of the Integrity Checker Tool.** Ivanti's built-in Integrity Checker Tool (ICT) is defeated by patching code in memory and restoring the original bytes afterward, so a post-incident ICT scan can come back clean even on a compromised appliance.
- **Post-root credential harvesting.** After reaching root, UTA0576 used a compromised Active Directory service account and a custom Python LDAP tool to search AD for LAPS local-administrator passwords, BitLocker recovery keys, and other password-bearing attributes - setting up for lateral movement well beyond the VPN appliance itself. Volexity confirmed exfiltration of domain credentials, limited AD metadata, and raw packet captures.

## What this means for defenders

The durable signal here isn't a malware hash or a C2 domain - it's the mismatch this chain depends on: a request whose actual destination (named in the `X-DSCGI-PATH` header) doesn't match the URL path the appliance's auth check evaluated. Because the attack lives entirely in web requests against the appliance and leaves no backdoor and a defeatable integrity check, organizations running Ivanti Connect Secure need to treat edge-appliance web logs and LDAP query auditing as primary detection surfaces, not an afterthought behind endpoint EDR - and should not treat a clean ICT scan alone as proof an appliance wasn't compromised.
